# 回答与笔记规范

## 技术问题的回答顺序（用户 2026-10-25 明确要求）

解释一个名词、函数、方法、机制或协议时，按这三步展开，顺序不要颠倒：

1. **是什么** —— 先用一两句话给定义和边界：它属于哪一层、解决什么问题、容易和什么混淆。不要一上来就给用法。
2. **横向对比** —— 同类技术有哪些，各自在哪个维度上取舍（时间复杂度 / 空间 / 有序性 / 实现代价 / 适用规模），为什么选它、什么时候不该选它。
3. **怎么用 / 应用场景** —— 最小可用的代码或步骤，加上「什么时候该用、什么时候别用」。

纯执行类请求（改文件、跑命令、整理笔记）不需要套这个结构。

## 笔记

`learn-note` 生成的条目，正文部分尽量沿用同一顺序：是什么 → 横向对比 → 用法与场景。速查卡保持 ≤5 行不变。
