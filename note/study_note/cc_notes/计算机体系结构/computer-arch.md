# 计算机体系结构

## SIMD、SIMT、脉动阵列分别是什么？为什么它们不是一回事？ #arch #cuda

> **速查**
> - 三个词分属**三个层面**：SIMD 在 ISA 指令级、SIMT 在架构/执行模型级、脉动阵列在数据流架构级
> - SIMD 与 SIMT 的差别在**谁负责打包**：SIMD 要程序员显式把数据塞进向量寄存器；SIMT 写标量代码，硬件替你并行
> - 只有 SIMT **允许同一个 warp 内分支发散**（靠硬件维护的重汇聚栈把两条路径串行化）；SIMD 得用掩码自己绕
> - 脉动阵列和另两个不在同一条轴上——**它没有指令、没有 PC**，行为由流片时焊死的互连拓扑决定
> - 核心轴一句话：**SIMD/SIMT 是指令驱动，脉动阵列是数据驱动**

### 正文

**① 三个层面**

| 概念                                                   | 层面             | 一句话                                                             |
| ---------------------------------------------------- | -------------- | --------------------------------------------------------------- |
| **SIMD**（Single Instruction Multiple Data，单指令多数据）    | **ISA 指令级**    | 一条指令作用在一个**向量寄存器**上。谁把数据打包成向量？程序员或编译器                           |
| **SIMT**（Single Instruction Multiple Threads，单指令多线程） | **架构 / 执行模型级** | 硬件同时管大量**线程**，每条线程有自己的寄存器和 PC；一个 warp 调度器把同一条指令发给 32 个 lane     |
| **脉动阵列**（systolic array）                             | **数据流架构级**     | 大量极简 PE（processing element，处理单元）排成网格，数据在相邻 PE 间有节奏地流动。**它没有指令** |

**② SIMD 和 SIMT 最容易混，分界在「谁负责打包」**

- **SIMD**：你写 `_mm256_add_ps(a, b)`——得先把 8 个 float 摆进向量寄存器。**并行的责任在软件。**
- **SIMT**：你写 `c[i] = a[i] + b[i]` 这种**标量代码**，硬件把它并行化。**并行的责任在硬件。**

第二个分界是**分支**：

|      | 同一组 lane 走不同分支时                                                                       |
| ---- | ------------------------------------------------------------------------------------- |
| SIMD | 语言/ISA 层面没有这个概念。要么用掩码自己绕，要么展开成两条路径各算一遍                                                |
| SIMT | 硬件支持——warp 内线程可以走不同分支，**重汇聚栈**（reconvergence stack）记录分叉点，两条路径**串行**执行，每条只激活走这条路的 lane |

SIMT 的 divergence 不是免费的（串行化意味着 lane 空转），但它是**硬件自动处理**的；SIMD 里这笔开销得程序员自己算。

**③ 真正的分界线：指令流 vs 数据流**

> **SIMD / SIMT 是「指令驱动」的**：有一个程序计数器在决定下一步做什么。运算单元是通用的，行为由**指令**决定。
>
> **脉动阵列是「数据驱动」的**：**没有 PC、没有指令**。每个 PE 每周期做的是同一件固定的事，行为由**互连拓扑**决定——而互连是流片时焊死的。

这一条推出后面所有的差异。它们不是"两种实现同一个东西的方法"，而是**两种不同的计算范式**——脉动阵列根本执行不了"程序"。

**④ 为什么这条轴这么重要**

因为它决定的不是"快慢"，而是"**能不能跑**"：

- 指令驱动的机器，**任何能在 ISA 上表达的程序都能跑**，代价是每周期要花面积和功耗去取指、译码、调度。
- 数据驱动的机器，**只有编译期能把数据流映射成那个固定拓扑的算子能跑**。换算子 = 重新映射（甚至重新设计硬件）。

## 脉动阵列的硬件每周期在做什么？峰值吞吐怎么算？ #arch #systolic-array

> **速查**
> - 每个 PE 只有一个**静止的权重** + 每周期从上方收部分和、从左方收激活值；算 `p_out = p_in + w · x`，把 `x` 推给**右邻**、`p_out` 推给**下邻**
> - **没有取指、没有译码、没有寄存器堆多端口读取、没有 scoreboard、没有分支预测**——脉动阵列就是拿控制换运算
> - **硬件**：互连和 PE 是固定电路，数据每拍移一格是硬连线的；**软件**（编译器）：切 tile、排权重加载顺序、做双缓冲
> - 峰值 = PE 数 × 频率 × 2（一次 MAC = 1 乘 + 1 加，算 2 个 op）：`256 × 256 × 700 MHz × 2 = 91.7 TOPS`
> - 它是 **weight-stationary**（权重静止）：权重预加载后不动，**激活和部分和在网格里脉动**

### 正文

**① PE 的机制（以 TPU v1 的 256×256 MXU 为例）**

网格共 `256 × 256 = 65536` 个 PE。每个 PE 的全部状态只有：

- 一个**静止**的权重 `w`
- 每周期从**上方**收到部分和 `p_in`，从**左方**收到激活值 `x`
- 算一件事：`p_out = p_in + w · x`
- 把 `x` 推给**右邻**，把 `p_out` 推给**下方**

就这样。**没有取指、没有译码、没有寄存器堆多端口读取、没有 scoreboard。**

**"脉动"这个词说的是数据每拍移一格这件事**：激活值从左侧按行进入、每周期右移一格；部分和从上往下走。整个阵列由同一套时钟节拍驱动，像泵一样。

**② 软硬件怎么分工**

| 谁 | 做什么 |
|---|---|
| **硬件** | 互连拓扑、PE 的运算、数据每拍移一格——全是固定电路 |
| **软件**（XLA 这类编译器） | 把算子**映射**成这个形状：切 tile、决定权重加载顺序、安排双缓冲、把大矩阵拆成能喂进阵列的块 |

**换算子只重编译，硬件不动**——这是它相对 ASIC 的优势，也是它相对 GPU 的劣势（见下一条）。

**③ 峰值怎么算出来的（能手验）**

```
256 × 256        = 65536 个 MAC 单元
× 700 MHz
× 2              （一次 MAC = 1 乘 + 1 加，算 2 个 op）
= 9.17 × 10¹³    = 91.7 TOPS (int8)
```

TPU v1 论文（Jouppi et al., ISCA 2017）报的就是 92 TOPS。

**这正是脉动阵列的好处：峰值吞吐 = PE 数 × 频率，没有别的系数。** 没有"实际能到峰值的百分之几取决于指令混合"这种事——只要数据流对，每个 PE 每拍都在干活。

**④ 对照：SIMT 的 SM 在做什么**

一个 NVIDIA SM 里有一整套控制逻辑：**取指单元、译码器、若干 warp 调度器、每线程最多 255 个寄存器的寄存器堆、分支重汇聚栈**。每周期每个调度器挑一个 warp，发射它的**一条**指令给 32 个 lane。

一个 warp 执行 1 条 FMA = 32 次乘加，但为了这 32 次运算，硬件要先取出、译码、调度这条指令，还要从寄存器堆里读 3 个操作数。

> **对 GEMM 这种控制流完全静态的负载，这部分开销是纯浪费。** 脉动阵列就是把这块面积和功耗整个换成 PE——这是同一枚硬币的两面。

**⑤ 流水线填充**

阵列不是一开始就满的：第一个激活值要从最左列一路脉动到最右列，部分和要从最上行走到最下行。**要填满 256×256 的网格，需要约 256 拍的填充**。

所以"峰值 92 TOPS"有前提——**`K`（累加深度）得足够大**，否则填充和排空占的比例就很高。这条直接连到下一条笔记的死穴。

## 脉动阵列和 SIMT 各自的优劣与死穴在哪？ #arch #systolic-array #performance

> **速查**
> - 脉动阵列的**死穴是形状错配**：256×256 阵列算 16×16×16，活跃 PE 只有 256 个，利用率 **0.39%**
> - **LLM 自回归解码的 `M = 1` 正面撞上这个死穴**——所以脉动阵列天然需要大 batch
> - SIMT **没有"阵列形状"这个概念**：线程映射到输出元素，只要 `N` 够大就能打满，退化是平滑的
> - GPU 处理小矩阵同样低效，但原因是**启动开销和占用率**，不是结构性错配——前者能靠 batching 摊薄，后者不能
> - 现实中是**融合**：Tensor Core = SM 里塞的一小片脉动阵列；TPU 旁边的 VPU = 兜非 GEMM 算子的通用单元

### 正文

**① 正面对比**

| 维度 | 脉动阵列 | SIMT（GPU） |
|---|---|---|
| 控制方式 | 数据流，行为固化在互连里 | 指令流，每周期取指译码 |
| **可编程性** | 只有编译期能映射的算子能跑；换算子要重新映射 | 任意程序，指令级可编程 |
| **形状适应性** | **差**——矩阵非方或太小 → 利用率崩（见下） | 好——线程映射到输出元素，**退化平滑** |
| 每 MAC 的能效 | 高（无取指 / RF / 调度开销） | 低（控制开销虽被摊薄但存在） |
| 面积效率 | 高（PE 极小） | 低（寄存器堆 + 调度器占大头） |
| 分支 | 没有分支这个概念 | 支持，但 divergence 时 lane 空转 |
| 主要瓶颈 | **片上互连 + 权重预加载带宽** | 寄存器堆带宽、divergence |
| 编程抽象 | 算子库 / 编译器（XLA） | CUDA / 任意语言 |
| 代表 | TPU v1–v4 MXU、华为达芬奇、寒武纪 | NVIDIA SM、AMD CU、Intel Xe |

**② 死穴：利用率对矩阵形状极度敏感（这个能当场算）**

还是那个 256×256 的阵列，算 `M×K×N` 的矩阵乘：

| 场景 | 活跃 PE 数 | 利用率 |
|---|---|---|
| 256×256×256 | 65536 | 100% |
| 128×128×128 | 16384 | 25% |
| **16×16×16** | **256** | **0.39%** |
| **LLM 自回归解码，`M = 1`** | **1 行 × 256** | **≤ 0.39%** |

`256 ÷ 65536 = 0.39%` —— 三个维度**都得 ≥ 256** 才能填满。这就是为什么 TPU 需要大 batch，也是为什么**逐 token 解码在脉动阵列上天然吃亏**（每步只有一个 token，`M = 1`）。

**③ 反例（当场失败的那一侧）**

同样算一个 `M = 1` 的矩阵乘，**GPU 怎么做**？它把**线程映射到 `N` 个输出元素**上。`N = 4096` 就派 4096 个线程，每个线程串行累加 `K` 次。

**只要 `N` 够大，SM 就能打满**——形状不匹配根本不存在，因为 **GPU 没有"阵列形状"这个东西**。

> 但别把话说成"GPU 处理小矩阵就没问题"。GPU 也低效，**只是原因完全不同**：是 kernel 启动开销和占用率不足，**不是结构性的形状错配**。这个区别很要紧——前者能靠 batching 摊薄，后者只能靠换硬件。

**④ 顺带解释：tiling 为什么存在**

把大矩阵切成 256×256 的块喂给阵列，就是在**人为制造形状匹配**。

| tile 太小 | tile 太大 |
|---|---|
| 阵列用不满 | 放不进片上 SRAM，要频繁往返 DDR |

这个取舍是脉动阵列芯片设计的核心问题之一。

**⑤ 现实中不是二选一**

**Hopper 起的 Tensor Core（以及 Blackwell 的 `tcgen05`）本质上是「每个 SM 里塞了一小片脉动阵列」：**

- 做的是**固定形状**的矩阵乘（如 `m16n8k16`），数据流固化、**不可编程**——这是脉动阵列的特征
- 但它活在 SM 里，由 **warp 调度器发射**、由 SIMT 的寄存器堆喂数据——这是 SIMT 的特征

同理，**TPU 也不是纯脉动阵列**——它旁边配了一个 **VPU**（vector processing unit，通用向量单元），专门处理 softmax、LayerNorm 这类脉动阵列做不了的 element-wise / 归约算子。

| | 脉动阵列芯片 | SIMT GPU |
|---|---|---|
| 算力主力 | 阵列（不可编程） | SM（可编程） |
| 配套单元 | VPU（兜非 GEMM 算子） | Tensor Core（兜 GEMM） |
| 极端情况 | 只跑 GEMM 极快，跑别的很慢 | 什么都能跑，跑 GEMM 不如专用硬件划算 |

**⑥ 一句话总结这个 trade-off**

脉动阵列是在「**我知道接下来一百万拍每一步做什么**」这个前提下，把**控制**的面积和功耗全部兑换成**运算**。

代价是：一旦程序的控制流不是编译期可静态确定的，这笔兑换就作废——因为那个阵列**不知道怎么"改变主意"**。

## 数据流怎么选？复用因子怎么算？ #arch #dataflow

> **速查**
> - **数据流（dataflow）** = 决定「哪份数据留在片上、哪份流动」的策略，属于**硬件设计决策**（由互连和控制器固化），不是算法选择
> - 四类：权重驻留 WS / 输出驻留 OS / 输入驻留 IS / 行驻留 RS。**判断依据是哪个维度的复用最高**
> - **复用因子** = 同一份数据被用了几次。同一个 1024×4096 INT8 权重（4.19 MB）：`M=1` 算术强度 **2 OPS/byte**，`M=512` 是 **630 OPS/byte** —— 差 **315 倍**（不是 512 倍）
> - 片上 SRAM 装不下的部分要分块重读 → **复用打折、DRAM 流量上升**。切分时优先切「复用最低」的维度
> - **复用本身就是 1 时，数据流救不了你** —— `M=1` 的 decode 唯一有效杠杆是减少权重字节数

### 正文

**① 数据流是哪一层的东西**

数据流回答一个问题：**一次计算里，W（权重）、X（输入）、Y（输出/部分和）三份数据，哪份固定在运算单元上、哪份在片上流动、哪份去 DRAM 往返？**

它由**硬件**决定——PE 之间的连线和片上 buffer 的组织方式焊死了数据怎么走；**软件**（编译器）只能在给定拓扑下决定切块顺序和加载时机。

所以：**数据流是硬件能力，调度是软件工作。** 换个数据流 = 重新设计芯片，不是重编译。

**② 四类数据流对照**

| 数据流 | 谁留在 PE 里 | 谁在流动 | 什么时候占优 |
|---|---|---|---|
| **权重驻留 WS**（weight stationary） | 权重 `W` | 激活、部分和 | **`M` 大**（batch / prefill）—— 权重被 M 个输入共享 |
| **输出驻留 OS**（output stationary） | 部分和 | 权重、激活 | 卷积；输出小、权重也小 |
| **输入驻留 IS**（input stationary） | 激活 `X` | 权重 | **`N` 大**（输出通道多）—— 输入被 N 个输出共享 |
| **行驻留 RS**（row stationary，Eyeriss 提出） | 一行输入 + 一行权重 | 其余 | 卷积；把一维卷积的行钉在 PE 里，输入和权重同时复用 |

**③ 复用因子 —— 一个能手算的例子**

取 GR00T 的一层 FFN 权重：`K=1024`、`N=4096`、INT8。

```
W 体积 = 1024 × 4096 × 1 B = 4,194,304 B = 4.19 MB
运算量 = 2 × M × K × N
```

**三种数据的复用因子：**

- `W[k,j]` 被 **M 个**输入共用 → 复用 **M** 次
- `X[i,k]` 被 **N 个**输出共用 → 复用 **N** 次
- `Y[i,j]` 被累加 K 次，但它是累加器，**不重复读写**

**代入两个 M：**

| | `M=1`（decode） | `M=512`（prefill） |
|---|---|---|
| 运算量 | 8,388,608 FLOP = 8.39 MFLOP | 4,294,967,296 FLOP = 4.29 GFLOP |
| W 搬运 | 4.19 MB | 4.19 MB |
| X 搬运 | 1,024 B ≈ 1 KB | 524,288 B = 0.52 MB |
| Y 搬运 | 4,096 B ≈ 4 KB | 2,097,152 B = 2.10 MB |
| **总搬运** | **4.199 MB** | **6.816 MB** |
| **算术强度** | **2.00 OPS/byte** | **630 OPS/byte** |

**当场验算：**
```
M=1  : 8,388,608 ÷ 4,199,424  = 2.00
M=512: 4,294,967,296 ÷ 6,815,744 = 630.1
```

**为什么不是 512 倍？** 因为只有 `W` 被摊薄，`X` 和 `Y` 随 M 线性增长。`M=512` 时权重只占总搬运的 **61.5%**（4.19 ÷ 6.82）。这一条容易被说成"差 512 倍"——是把 X、Y 漏算了。

**④ 片上容量怎么给复用打折（tiling 的经济理由）**

设片上 SRAM 只有 **2 MB**，而 `W` 要 **4.19 MB** → **装不下**，必须切块。

```
块数 = ⌈4.19 ÷ 2.0⌉ = 3 块，每块约 1.40 MB
```

两种切法，后果不同：

| 切法 | 谁被重读 | 总流量（M=512） | 算术强度 |
|---|---|---|---|
| **切 N**（输出通道分 3 块） | `X` 重读 3 次 | 4.19 + 3×0.52 + 2.10 = **7.86 MB** | **546 OPS/byte** |
| **切 M**（batch 分块） | `W` 重读 ⌈M/M_tile⌉ 次 | 权重每块重读一遍，涨幅远大于上者 | 更低 |

**决策规则：优先切分「复用最低」的那个维度。**

`M=512` 时 `W` 复用 512 次、`X` 复用 4096 次——所以宁可让 `X` 重读，也不能让 `W` 重读。

代价是算术强度从 **630 掉到 546**（−13.3%）。这就是 tiling 不是免费的。

**⑤ 关键边界：复用等于 1 时，数据流无效**

`M=1` 时：

```
W 的复用因子 = M = 1
```

**权重只被一个输入用一次。** 那么无论选 WS 还是 IS、无论阵列做多大，`W` 都必须完整读一遍——**没有复用可摊薄**。

**所以 decode 的唯一有效杠杆是减少 `W` 的字节数**：量化、压缩。这不是"顺便优化一下"，是**唯一的路**。

反过来看 prefill：`M=512` 时权重占流量 61.5%，压掉一半权重只省 31% 的流量。**压缩在 decode 的收益远大于 prefill** —— 这个方向判断能直接用来解释"端侧为什么更需要压缩"。

**⑥ 反例：对 M=1 硬用权重驻留**

如果给 decode 配一个 WS 的阵列：

- 权重预加载进 256×256 阵列，只被 1 个输入用一次 → **预加载开销完全没有摊薄**
- 同时 M 维度上只有 1 行 PE 活跃 → 利用率 ≤ `1/256`
- **两个损失叠加**，比"只是利用率低"更糟
