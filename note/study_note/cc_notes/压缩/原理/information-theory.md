# 信息论根基

> **这是压缩算法系列的最底层。** 它回答两个问题：① 为什么压缩存在极限；② 极限由什么量刻画。
> 后面所有算法（Huffman、算术编码、LZ、ANS、PPM、变换编码……）都是在逼近这些界，或用工程代价换取逼近。
>
> **约定**：`log` 以 2 为底，单位 bit。
> **标注**：【理论】= 定义/定理/可证明的界；【工程】= 0.对实际压缩器的约束或指导。

## 信息量为什么是 $-\log_2 p$？ #compression #theory

> **速查**
> - **$\log_2$ 数的不是"概率"，是"二分了几次"**——8 个等可能候选要问 3 次是/否，$\log_2 8 = 3$
> - 四条要求把函数形式**唯一钉死**：连续 · $I(1)=0$ · 单调递减 · **可加性 $I(p\cdot q) = I(p)+I(q)$**
> - **可加性是决定性的**：独立事件的信息必须相加
> - ⚠️ **换别的函数会在具体例子上当场失败**（$1-p$ 不行、$1/p-1$ 也不行）
> - 连续 + 单调 + 可加 ⟹ **只能是 $-c\cdot\log p$**
> - 选底数 2 只是单位约定：让 $I(1/2) = 1$，于是"一次抛硬币 = 1 bit"

### 正文

**先看一个能数出来的场景**——我在 1~8 里想一个数，你只能问"是/否"：

```
第 1 问：劈成 1-4 / 5-8  → 排除一半
第 2 问：再劈一半        → 排除一半
第 3 问：再劈一半        → 定下来
```

**8 个可能 → 3 次**。而 $\log_2 8 = 3$。**$\log_2$ 就是"连续二分几次"的计数**。

换成概率语言：一个概率 `p` 的事件，相当于"从大约 `1/p` 个等可能的候选里脱颖而出"。

| 事件 | p | 多少个等可能候选 | 几次二分 | $-\log_2 p$ |
|---|---|---|---|---|
| 抛硬币正面 | 1/2 | 2 | 1 | **1 bit** |
| 4 面骰子出"3" | 1/4 | 4 | 2 | **2 bit** |
| 8 面骰子出"3" | 1/8 | 8 | 3 | **3 bit** |
| 猜中 1~100 的数 | 1/100 | 100 | ~7 | **6.64 bit** |

**用扑克验证"必须可加"**——一副 52 张：

```
抽到【黑桃A】           p = 1/52  →  -log₂(1/52) = 5.70 bit
抽到【任意A】           p = 4/52  →  -log₂(4/52) = 3.70 bit
已知是 A，抽到【黑桃】   p = 1/4   →  -log₂(1/4)  = 2.00 bit

   5.70  =  3.70  +  2.00
     ↑        ↑       ↑
   黑桃A     任意A   花色
```

**"抽到黑桃A"的信息量 = "抽到A" + "已知是A再定花色"。** 这不是巧合——**两步的信息加起来就是整体的信息**。这就是 $I(p\cdot q) = I(p) + I(q)$（$4/52 \times 1/4 = 1/52$，$3.70 + 2.00 = 5.70$）。

**换别的函数会当场失败**：

```
候选 ①  I(p) = 1 − p          （递减 ✓，I(1)=0 ✓）
  I(黑桃A) = 0.981    I(任意A) = 0.923    I(黑桃|A) = 0.750
  可加性要求 0.981 = 0.923 + 0.750 = 1.673   ✗

候选 ②  I(p) = 1/p − 1        （递减 ✓，I(1)=0 ✓）
  I(黑桃A) = 51       I(任意A) = 12       I(黑桃|A) = 3
  可加性要求 51 = 12 + 3 = 15                ✗
```

> **四条要求（连续 · $I(1)=0$ · 单调递减 · 可加性）联合起来，解唯一：$I(p) = -c\cdot\log p$。**
> 上面的候选都是在**具体牌例上当场失败**的。

**为什么是 log 而不是别的**：把可加性写成函数方程 $I(xy) = I(x) + I(y)$，换元 $x = e^s, y = e^t$ 得 $g(s+t) = g(s) + g(t)$（柯西加性方程）。由整数次 → 分数次 → 连续性推广，唯一解是 $g(t) = c\cdot t$，回代即 $I(p) = c\cdot\ln p$。

## 熵是什么？为什么它是压缩的下界？ #compression #theory

> **速查**
> - $H = \sum p_i\cdot I(p_i) = -\sum p_i \log_2 p_i$ —— **平均意外度**
> - 但它有个更硬的身份：**它就是「最优码表的平均码长」，能直接数出来**
> - **当所有 `pᵢ` 都是 2 的幂时，码长 $-\log_2 p_i$ 恰好是整数 → 熵 = 实际码长**（KL = 0）
> - ⚠️ **当 `pᵢ` 不是 2 的幂时，码长只能向上取整 → 实际码长 > 熵**。这就是 $H \le L < H+1$ 里那个 $+1$ 的来源
> - **极端例子**：$p = [0.9, 0.1]$ 的熵只有 **0.469 bit**，但任何前缀码至少要 **1 bit** —— 浪费掉 0.531 bit
> - 取值：$0 \le H \le \log_2|\Sigma|$（退化分布 = 0；均匀分布 = $\log_2|\Sigma|$。字节的均匀分布 = **8 bit**，正是原始字节表示）

### 正文

**为什么它是"信息量的期望"**：这是 Shannon 从三条公理推出来的**结果**，不是假设——① 连续性 ② 等概率时 $A(n)$ 随 n 递增 ③ **分组可加性**（一次选择分两阶段做，`H` = 各阶段加权和）。由 ③ 推出的唯一形式就是 $-\sum p \log p$。

**但更好理解的方式是直接数码长**——把熵当"最优码表的平均码长"算一遍：

**场景 1：公平 4 面骰子**

```
每个面 p = 0.25, I = 2 bit
码表：00 / 01 / 10 / 11  → 每报一次 2 bit

熵       = 0.25×2 × 4 = 2 bit
实际码长 = 2 bit                    ✓ 相等
```

**场景 2：作弊骰子 $p = [0.5, 0.25, 0.125, 0.125]$**

```
I  = [1, 2, 3, 3]
熵 = 0.5×1 + 0.25×2 + 0.125×3 + 0.125×3 = 1.75 bit

码表：面1→0   面2→10   面3→110   面4→111     （前缀码，不会混淆）
实际平均 = 0.5×1 + 0.25×2 + 0.125×3 + 0.125×3 = 1.75 bit   ✓ 又相等
```

**为什么这两个能相等**：所有 `pᵢ` 都是 **2 的幂**，$-\log_2 p_i$ 正好是整数。

**场景 3：均等 3 面骰子 —— 这里就不相等了**

```
每个面 p = 1/3, I = 1.585 bit
熵 = 1.585 bit                      ← 理论下界

但码长必须是整数！前缀码只能这么分：{0, 10, 11}
实际平均 = (1 + 2 + 2)/3 = 1.667 bit

1.667  >  1.585                     ← 差了 0.082 bit
```

**场景 4：极端情况，损失有多大**

```
p = [0.9, 0.1]
I  = [0.152, 3.322]
熵 = 0.9×0.152 + 0.1×3.322 = 0.469 bit

但两个符号最少也得一人 1 bit（码字 0 和 1）：
实际平均 = 1 bit

1  >  0.469                         ← 差了一倍多
```

> **$H \le L < H+1$ 里那个 $+1$ 的具体来源就是场景 3、4**：概率不是 2 的幂时，$-\log_2 p$ 不是整数，取整就多花。
> **这也是为什么需要算术编码**——它不做"整数码长"，能把 0.469 逼近到接近 0.47。

**为什么它同时是压缩的下界**：上面数的是"最优码表的平均码长"，而**没有任何码表能比最优码表更短**。所以 $L \ge H$ 是"最优"这个词的直接后果（严格推导见「交叉熵与 KL 散度」一节）。

## 条件熵与互信息：为什么"利用上下文"能降熵 #compression #theory

> **速查**
> - **链式法则**：$H(X,Y) = H(X) + H(Y|X)$ —— 把两个变量一起记，bit 数 = 先记 X + 已知 X 后记 Y
> - **互信息** $I(X;Y) = H(X) - H(X|Y) \ge 0$，即 **$H(X|Y) \le H(X)$：条件化永不增加熵**
> - 一切上下文建模压缩器（LZ、PPM/CM、LLM 预测）都在做同一件事：**把估值从 $p(x)$ 换成 $p(x \mid \text{上下文})$**
> - **压缩器的本质就是上下文的函数**
> - 符号独立时 $H(X^n) = n\cdot H(X)$，上下文无用；符号相关时 $H(X^n) < n\cdot H(X)$，省下 $\sum I(X_i; X^{<i})$ bit

### 正文

**条件熵**：$H(Y|X) = \sum_x p(x)\cdot H(Y|X=x)$——"已知 X 后 Y 的剩余不确定度"，即"对每个 x 先算 $H(Y|X=x)$，再按 $p(x)$ 加权平均"。

**链式法则**：$H(X,Y) = H(X) + H(Y|X)$，推广到 n 个变量：

$$
H(X_1,\dots,X_n) = \sum_i H(X_i \mid X_{i-1},\dots,X_1)
$$

**这个求和式是"上下文为什么有用"的数学核心。**

**互信息**：$I(X;Y) = H(X) - H(X|Y) \ge 0$（$I = 0$ 当且仅当两者独立）。

由 $I \ge 0$ 立即得到 $H(X_i | X_{i-1},\dots,X_1) \le H(X_i)$——**"已知前面符号后，下一个符号的剩余熵"不会超过它的边际熵**。

代入链式求和：一条 n 长消息的总熵等于各步条件熵之和；**只要数据里有可被前面符号预测的部分（$I > 0$），对应项就比"当作独立符号"小**。

**工程含义**：一切上下文建模压缩器都在做同一件事——把估值从边际分布 $p(x)$ 换成条件分布 $p(x \mid \text{上下文})$，从而逼近更小的条件熵。**压缩器的本质就是上下文的函数。**

## 香农源编码定理：无损压缩的极限在哪 #compression #theory

> **速查**
> - **Kraft 不等式**：一个 D 进制前缀码存在，当且仅当码长满足 $\sum D^{-l_i} \le 1$
> - **香农第一定理**：无记忆源存在前缀码使 $H(X) \le L < H(X) + 1$
> - ⚠️ **那个 $+1$ 是整个码字表的总损失，不是每符号的税** —— 这是最容易记错的一点
> - **它从哪来**：理想码长 $-\log_2 p(x)$ 一般**不是整数**（如 $p=0.3$ → 1.74 bit），整数码字必须向上取整
> - **怎么消掉**：**块编码**（n 个符号打包成超符号）→ 每符号税降到 $1/n \to 0$；**算术编码**用区间细分达到这一极限，无需真造指数级码表
> - 下界 $L \ge H$ 的机制：$L - H = D(p\|q) \ge 0$（**KL 散度**，见后文专条）

### 正文

**Kraft 不等式**：一个二元前缀码的码长 $l_1\dots l_n$ 必须满足 $\sum 2^{-l_i} \le 1$。

**树形直观**：把 $[0,1)$ 看成根节点，每往下一层就把区间劈成两半：

```text
                    [0,1)
             0 /            \ 1
           [0,0.5)        [0.5,1)
          0/    \1        0/    \1
       [0,.25) [.25,.5) [.5,.75) [.75,1)
```

- 深度为 $l$ 的节点占据宽度 $2^{-l}$
- 一个码字 = 选一个叶子
- **前缀码** = 选中的叶子互不为祖先/后代 → 它们的区间**互不重叠**
- 所有区间都在 $[0,1)$ 内，所以总宽度 ≤ 1

**三个手算例子**（先数宽度，再看合法性）：

```text
✅ {0, 10, 110, 111}   码长 1,2,3,3
   1/2 + 1/4 + 1/8 + 1/8 = 1
   0   → [0,     0.5)
   10  → [0.5,   0.75)
   110 → [0.75,  0.875)
   111 → [0.875, 1)          ← 刚好铺满，完整码

✅ {00, 01, 10, 110, 111}   码长 2,2,2,3,3
   3/4 + 2/8 = 1
   00  → [0,     0.25)
   01  → [0.25,  0.5)
   10  → [0.5,   0.75)
   110 → [0.75,  0.875)
   111 → [0.875, 1)          ← 也刚好铺满

❌ {0, 01, 10, 11}   码长 1,2,2,2
   1/2 + 1/4 + 1/4 + 1/4 = 1.25 > 1
   而且 0 是 01 的前缀 → 区间 [0,0.5) 与 [0,0.25) 重叠
```

⚠️ **Kraft 约束的是码长，不是某一套具体码字**。码长 `1,2,2` 满足 Kraft，但 `{0, 01, 11}` 本身不是前缀码；`{0, 10, 11}` 才是。Kraft 保证“这组码长有解”，不保证“你随手写的这套码字合法”。

**为什么必须满足**：把每个码字 `c` 映射到实数区间 $[0.c, 0.c + 2^{-len})$，即把码字当成二进制小数。

- 长度 `l` 的码字占据宽度 $2^{-l}$ 的区间；
- 因为是前缀码，任一码字不是另一个的前缀 → 任意两个码字的区间**互不相交**；
- 所有区间都在 `[0,1)` 内。

总宽度 ≤ 1，直接得出。**McMillan 定理**进一步说明：对任何**唯一可解码**的码，Kraft 同样成立。所以**最优前缀码 = 最优唯一可解码码**。

**定理**：无记忆源存在无前缀二进制码使 $H(X) \le L < H(X) + 1$，其中 $L = \sum p(x)\cdot l(x)$ 是平均码长。

**上界那 1 bit 的来源**（回答"为什么整数比特带来损失"）：

取 $l(x) = \lceil-\log_2 p(x)\rceil$（向上取整），则：

1. $2^{-l(x)} \le p(x)$，故 $\sum 2^{-l(x)} \le \sum p(x) = 1$ —— **Kraft 满足**，前缀码存在；
2. $l(x) < -\log_2 p(x) + 1$，加权求和得 $L < H(X) + \sum p(x) = H(X) + 1$。

**机制**：理想码长一般是**非整数**。整数码字必须向上取整，每个符号多花"不到 1 bit"，按概率加权后总额外开销也"不到 1 bit"。**所以它不是每符号 1 bit 的固定税，而是每传一个码字最多 1 bit 的边界税。**

**如何消掉**：

- **块编码**：把 n 个符号打包成"超符号"再编码 → $L_n/n < H(X^n)/n + 1/n$。对无记忆源 $H(X^n) = nH(X)$，得 $L_n/n \to H(X)$，**每符号的 1 bit 税摊成 1/n 并趋于 0**。
- **算术编码**：把整条消息映射到 `[0,1)` 上一个子区间，用区间内一个点表示消息。消息概率 $P = \prod p(x_i)$，区间长度恰为 $P = 2^{-L*}$，其中 $L* = -\sum\log_2 p(x_i)$。输出约 $\lceil L*\rceil+1$ bit，即 **$n\cdot H + O(1)$**——**$O(1)$ 与 n 无关，而不是 n 的每符号税**。

**渐近均分性（AEP）**：对 i.i.d. 源，$-(1/n)\log_2 p(X^n) \to H(X)$（依概率）。于是"典型集"大小约 $2^{nH}$，用 $n(H+\varepsilon)$ bit 定长编码即可，且不可能再用更少。

## 交叉熵与 KL 散度 #compression #theory

> **速查**
> - **核心等式**：$\text{交叉熵} = \text{熵} + \text{KL 散度}$ → **$H(p,q) = H(p) + D(p\|q)$**
> - $H(p)$ = **理论极限**（即使模型完美也得付）；$D(p\|q)$ = **犯错多付的**；$H(p,q)$ = **实际付账**
> - **交叉熵的物理身份**：**用错码表的平均码长** —— 码长 $l_i = -\log_2 q_i$（`q` 是码表隐含的分布），所以 $L = \sum p_i(-\log_2 q_i) = H(p,q)$
> - **为什么用 `p` 加权、`q` 算信息量**：`p` = 数据真实来自哪里（决定每种情况**被数多少遍**）；`q` = 码表按什么设计的（决定**每个符号花几比特**）
> - **$H(p,q) \ge H(p)$** 等号 ⟺ $p = q$ —— **"用错的模型不可能更好"**
> - ⚠️ **KL 不对称**：$D(p\|q) \ne D(q\|p)$，因为它**只惩罚 $p_i > 0$ 的地方**
> - **为什么它是 ML 的损失函数**：`p` = 真实标签、`q` = 模型预测；最小化交叉熵 ≡ 最小化 KL（因为 $H(p)$ 是常数）

### 正文

**先把它数出来**——360 天的天气播报，**真实分布** `p`：晴 180 天、雨 90 天、阴 90 天。

**最优码表**（基于正确的 p）：

```
晴 → 0  (1 bit)    雨 → 10 (2 bit)    阴 → 11 (2 bit)

全年总比特 = 180×1 + 90×2 + 90×2 = 180 + 180 + 180 = 540 bit
平均每天   = 540 / 360 = 1.5 bit          ← 正好是熵
```

**一个错的码表**（我以为阴天很常见，$q = [0.25, 0.25, 0.5]$）：

```
晴 → 00 (2 bit)    雨 → 01 (2 bit)    阴 → 1 (1 bit)

全年总比特 = 180×2 + 90×2 + 90×1 = 360 + 180 + 90 = 630 bit
平均每天   = 630 / 360 = 1.75 bit         ← 这就是交叉熵
```

**关键对照**：

```
交叉熵 = 0.5×2 + 0.25×2 + 0.25×1     ← 用真实频率 p 加权，用错误码表的码长 (-log₂q)
熵     = 0.5×1 + 0.25×2 + 0.25×2     ← 用真实频率 p 加权，用正确码表的码长 (-log₂p)
```

- **"用 `p` 加权"**：晴天真有 180 天，所以"晴"那 2 bit 要被数 180 次。**数据的真实频率决定每种情况被数多少遍。**
- **"用 `q` 算信息量"**：码长是按你的码表定的，而码表按 `q` 设计 → $\text{码长} = -\log_2 q$。

**差额可以数出来**：

```
630 − 540 = 90 bit（一年）
90 / 360  = 0.25 bit（每天） =  KL 散度
```

**$D(p\|q) \ge 0$ 的例证**——固定 $p = [0.9, 0.1]$，把 `q` 试遍：

| 你以为的 `q` | $D(p\|q)$ |
|---|---|
| `[0.1, 0.9]`（完全反了） | **2.536** |
| `[0.5, 0.5]` | **0.531** |
| `[0.8, 0.2]` | **0.053** |
| **`[0.9, 0.1]`（想对了）** | **0** ← 最小 |
| `[0.95, 0.05]` | 0.030 |
| `[0.99, 0.01]` | 0.208 |

**最小值出现在 $q = p$，且恰为 0；往两边偏都变大；试不出负数。**

**为什么不可能为负**（说得通的理由）：`D` 的物理含义是"用错码表**多花的**比特"，而 $H(p)$ 是"用**最优**码表花的比特"。**"用错的"怎么可能比"用最优的"花得更少？"最优"这个词本身就禁止了这件事。** 所以 $\text{交叉熵} \ge \text{熵}$ 即 $D \ge 0$，等号 ⟺ 你这个"错的"恰好就是最优的 ⟺ $q = p$。

**不对称的来源**——看每一项的符号：

| 情况 | $\log_2(p_i/q_i)$ |
|---|---|
| $p_i > q_i$（真实比你以为的更常见） | 正项 |
| $p_i < q_i$（真实比你以为的更罕见） | 负项 |
| **$p_i = 0$（真实里不出现）** | **恒为 0，无论 qᵢ 是多少** |

**最后一条就是不对称的根源**：$D(p\|q)$ **只惩罚 $p_i > 0$ 的地方**。用 $p=[0.9,0.1]$、$q=[0.5,0.5]$ 验证：

```
D(p‖q) = 0.9·(+0.848) + 0.1·(-2.322) = +0.763 − 0.232 = 0.531
D(q‖p) = 0.5·(-0.848) + 0.5·(+2.322) = −0.424 + 1.161 = 0.737
```

**$D(q\|p)$ 更大，因为 0.5 的重量压在了 $\log_2 5 = 2.322$ 那个正项上。**

翻译成人话：

- $D(q\|p)$："我以为 50% 会发生的事（雨），真实只有 10%" → **我给雨分了超长的码，每次下雨吃大亏**
- $D(p\|q)$："真实 90% 会发生的事（晴），我以为只有 50%" → **我给晴分的码长了一点，但晴太常见，每次只多花一点点**

> **"罕见事件被分到超长码"比"常见事件被分到略长码"代价更大。**

**为什么它是 ML 的损失函数**：训练分类器时 `p` = 真实标签（one-hot）、`q` = 模型预测。$H(p)$ 是常数，所以**最小化交叉熵 ≡ 最小化 KL 散度**。当 `p` 是 one-hot 时，交叉熵退化成 $-\log_2 q(\text{真实类别})$——**只看模型给正确答案分配了多少概率**：

```
三分类，真实是"猫"
模型 A 预测 [0.7, 0.2, 0.1] → CE = -log₂(0.7) = 0.515   ← 好
模型 B 预测 [0.4, 0.5, 0.1] → CE = -log₂(0.4) = 1.322   ← 差
```

**连回压缩**：把 $q_i = 2^{-l_i}$ 代进香农定理的证明——**`q` 就是"码表隐含的分布"**：

```
平均码长 L = Σ pᵢ·lᵢ = Σ pᵢ·(-log₂qᵢ) = 交叉熵 H(p,q)
L − H = 交叉熵 − 熵 = D(p‖q) ≥ 0
```

> **"设计好的码表" 本质就是 "让码表隐含的分布 `q` 逼近真实分布 `p`"。**
> $q = p$ 时 KL = 0，平均码长**恰好等于熵**（这就是前面骰子的场景 1、2）；
> Huffman 做不到（码长必须整数，场景 3、4 就是损失），**算术编码能逼近，因为它允许概率级细分**。

## 无记忆源 vs 有记忆源：熵率 #compression #theory

> **速查**
> - **无记忆源**（i.i.d.）：$H(X^n) = n\cdot H(X)$，第 3 节的界就是最终答案
> - **有记忆源**：真实极限是**熵率** $H(\mathcal{X}) = \lim (1/n)H(X_1,\dots,X_n) = \lim H(X_n|X_{n-1},\dots,X_1)$（平稳过程下两式相等）
> - **有记忆时 $H(\mathcal{X}) \le H(X_1)$**，通常严格小于：**逐符号边际熵是"高估"**
> - **一阶马尔可夫源**：$H(\mathcal{X}) = H(X_2|X_1) = \sum_i \pi_i \sum_j P_{ij} \log_2(1/P_{ij})$（`P` 转移概率，`π` 平稳分布）
> - ⚠️ **自然语言的熵率至今没有收敛的定论**——即使上下文窗开到很大，实测码长仍缓慢下降、看不到平台期

### 正文

**为什么真实数据的"逐符号熵"不是真实极限**：文本、图像、音频都有**长程相关**（远距离依赖），不是有限阶马尔可夫。用"单符号频率分布"算熵（零阶熵）只是**上界**；真实极限是**熵率** $H(\mathcal{X})$，它需要任意长的上下文才能逼近。

> ⚠️ **重要补充**：对自然语言，即使把上下文窗口开到很大，实测码长仍在缓慢下降、**看不到平台期**。这意味着自然语言熵率的具体数值至今没有定论，甚至有人猜测它随 $N\to\infty$ 趋于 0。**不要把它当成一个已确定的常数。**

## Kolmogorov 复杂度与 MDL #compression #theory

> **速查**
> - **Kolmogorov 复杂度** $K_U(x) = \min\{|p| : U(p) = x\}$——生成 `x` 所需**最短程序的长度**，即"x 的最短描述"
> - **不变性定理**：换一台通用机，`K` 只差一个与 `x` 无关的常数 → 良定义
> - ⚠️ **不可计算**：不存在程序能对所有 `x` 算出 $K(x)$（否则可判定停机问题）
> - **绝大多数 n bit 串满足 $K(x) \ge n - O(1)$** —— 随机串不可压缩
> - **与熵的关系**：对可计算分布 `P`，$E[K(x)] = H(P) + O(1)$
> - **推论**：**任何实际压缩器都是 $K(x)$ 的一个上界**，而由不可计算性，**没有任何实际算法能保证达到它**

### 正文

**与香农熵的区别**：

- **对象不同**：香农熵是对**分布/信源**取平均（需先给定 `p`）；Kolmogorov 复杂度是**单个字符串**的属性（无需分布）
- **联系**：对可计算分布 `P`，$E_{x\sim P}[K(x)] = H(P) + O(1)$，且逐串地 $K(x) \le -\log_2 P(x) + O(1)$

**MDL（最小描述长度，Rissanen）**：描述 = **模型**部分 + **给定模型后的数据**部分，两部分长度之和即总描述长度。理论基座正是上面的关系：**寻找好的压缩器 = 从可计算分布族中选 `P`，使 $-\log P(x)$ 小**。

**为什么这条对本系列重要**：它给"压缩"一个绝对定义（最短描述），同时说明这个定义**在计算上不可达**。实际压缩器只能在可计算的分布族里逼近。

## 典型数据的实际熵（量级参考） #compression #data

> **速查**
> - ⚠️ **以下都是"取决于语料"的区间，不是普适常数**
> - **英文文本**：Shannon 1951 估计 **0.6–1.3 bit/字符**（常引 ≈1.0）；ASCII 原始是 **8 bit/字符** → **冗余约 87%**
> - ⚠️ **现代 LLM 给出的 0.66–0.69 bit/字符很可能乐观**（训练/测试集重叠、字母表口径不同，**不可与上表横比**）
> - ⚠️ 有研究指出熵率**不是固定常数**：儿童读物约 2 bpc，现代诗歌约 6 bpc，小说/论文接近 1 bpc
> - **中文**：零阶约 **9.6 bit/汉字**；含上下文约 **4–5 bit/汉字**（数值来自较早期文献，未复核）
> - **图像（无损）**：PNG 自然照片约 **11–12 bit/像素（约 2:1）**——自然照片是 PNG 最差的一类
> - **音频（无损）**：FLAC 通常压到原始 **50%–70%**；通用算法（ZIP）对 CD 音频只压 10%–40%

### 正文

**英文文本的各家估计**：

| 来源 | 数值 (bit/字符) | 备注 |
|---|---|---|
| Shannon 1951（n-gram 上界） | 4.03 / 3.32 / 3.1（单/双/三字） | 只考虑有限阶统计 |
| Shannon 1951（长程外推） | 0.6–1.3，约 1.0 | 人工实验，**仅一位受试者**，统计学上被后人质疑 |
| Cover & King 1978 | ≤ 1.25 | 上界 |
| Brown et al. 1992（trigram） | ≈ 1.75 | 模型上界 |
| Ren et al. 2019（众包猜字） | ≈ 1.22 | 大规模复现 |
| 现代 LLM 作预测器 | 0.66–0.69 | ⚠️ **很可能乐观**，口径不同 |

**关键对照**：ASCII 英文文本原始 = **8 bit/字符**。若真实熵率约 1 bit/字符，则**冗余度约 87%**（Shannon 原话常引"约 80% 冗余"，以随机文本 $\log_2 27 \approx 4.75$ bit/字符 为基准）。

**中文**：

- **零阶**（仅字符频率）：约 **9.6 bit/汉字**（汉字容量极限定律：字符集超过约 12366 后趋于 9.65）
- **含上下文的极限熵（声称为上界）**：约 **4–5.17 bit/汉字**（吴军、王作英 1996 给上界 5.17）
- **工程参考**：UTF-8 下一个常用汉字 3 字节 = 24 bit；GB2312 下 2 字节 = 16 bit

**音频**：CD 原始 16 bit × 44100 Hz × 2 声道 = **1411 kbit/s**。FLAC 通常压到 50%–70%；静音接近 0%，噪声/重金属可能只压到 80–90%。

## 可逆变换不降熵，那变换有什么用？ #compression #theory

> **速查**
> - ⚠️ **若变换 `T` 可逆（双射），则 $H(T(X)) = H(X)$** —— 熵不会因可逆变换减少哪怕 1 bit
> - 这一点常被"变换能压缩"的说法误导，**必须澄清**
> - **变换真正做的**：把**多信息 / 总相关** $C = \sum_i H(X_i) - H(X_1,\dots,X_n) \ge 0$ 推向 0
> - **机制**：若编码器对每个分量**独立**做熵编码，总码率是 $\sum H(X_i) \ge H(X^n)$，**浪费了 C bit**；去相关后 $\sum H(X_i) \to H(X^n)$，独立分量编码器就能命中联合熵
> - **一句话**：变换不降熵，它把熵重新"摆布"，**使一个结构简单的（分量的、可并行的）编码器能够命中联合熵**
> - **有损管线例外**：量化是多对一，**真正降熵**——这才是有损能大幅低于无损极限的原因

### 正文

$C = \sum_i H(X_i) - H(X_1,\dots,X_n) \ge 0$，$C = 0$ 当且仅当各分量**相互独立**。$C > 0$ 说明分量间有统计依赖，"分开各自编码"会浪费 `C` bit。

**常见去相关手段**【工程】：

- **线性/正交变换**：KLT（Karhunen-Loève，即 PCA 在信号上的形式，使分量方差互不相关且能量最集中）、DCT（JPEG/视频用）、色彩变换 RGB→YCbCr、小波变换（JPEG 2000）
- **预测去相关**：DPCM / 线性预测（音频）——对每个样本记"与预测值的残差"，残差的条件熵远小于原样本边际熵（等价于第 2 节的上下文降熵在数值信号上的应用）

这些变换在**无损管线**里必须严格可逆（整数小波、整数 DCT/lifting 方案）。

**有损管线的额外机制**：变换后接**量化**。量化是多对一映射，**不可避免地丢弃信息、真正降低熵**——这才是有损压缩能大幅低于无损极限的原因。

**所以两条界要分清**：

| 管线 | 支配它的界 |
|---|---|
| 可逆变换 + 无损熵编码 | 无损极限（$H(X)$ / 熵率） |
| 变换 + 量化 + 熵编码 | 有损率失真曲线 $R(D)$ |

## 一页速览（结论链）

1. **$I(p) = -\log_2 p$** 数的是"二分几次"；四条要求（连续·$I(1)=0$·递减·**可加**）把它唯一钉死——扑克那个 $5.70 = 3.70 + 2.00$ 就是可加性的现场验证。
2. **$H = \sum p\cdot I$** 就是**最优码表的平均码长**，能数出来；`pᵢ` 是 2 的幂时恰好相等，否则必然多花（$p=[0.9,0.1]$ 熵 0.469 但实际只能做到 1 bit）。
3. **香农定理** $H \le L < H+1$：那个 `1` 来自**整数码长向上取整**，是**每码字**的边界税；块编码/算术编码把每符号税压到 $O(1)/n \to 0$。
4. **交叉熵** = 用**错码表**的平均码长；**KL** = 多花的那部分。$\text{交叉熵} = \text{熵} + \text{KL}$（天气那个例子：$630 = 540 + 90$）。
5. **$KL \ge 0$** ⟹ $\text{交叉熵} \ge \text{熵}$ ⟹ **$L \ge H$**。KL 还解释了两件事：为什么"用错的模型不可能更好"，以及**为什么不对称**（它只惩罚 $p_i > 0$ 的地方）。
6. **条件熵/互信息**说明上下文的价值：估值从 $p(x)$ 换成 $p(x \mid \text{上下文})$。
7. **有记忆源**的真实极限是**熵率** $H(\mathcal{X})$，逐符号边际熵只是上界；熵率至今无确定数值。
8. **Kolmogorov 复杂度**给出"最短描述"的绝对定义，但**不可计算**——实际压缩器都只是它的上界。
9. **变换不降熵**，只把熵重新摆布，让简单编码器能命中联合熵；有损管线靠**量化**真正降熵。
