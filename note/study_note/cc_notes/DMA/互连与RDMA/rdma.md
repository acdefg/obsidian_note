# RDMA

## RDMA 是什么？ #dma #rdma

> **速查**
> - Remote Direct Memory Access：一个设备直接读写**另一台机器**的内存，途中不经过对端 CPU 和对端内核
> - 它取代的是传统 socket 路径的两次内存拷贝 + 两次上下文切换——在 100 Gbps 以上瓶颈是 CPU 而不是网络
> - 三个核心机制：**内存注册**（pin 页 + 把翻译表交给网卡）、**队列对 QP**（描述符环）、**完成队列 CQ**
> - **内存注册就是 pinned memory 问题**——网卡要自己翻译地址，所以页必须固定、翻译表必须预算好
> - 最关键的区分：**单边**（Read/Write，对端进程毫不知情）vs **双边**（Send/Recv，对端必须先投递 buffer）

### 正文

**取代的那条路径**：

```
传统 socket：
应用 buffer → 内核 socket buffer → 网卡 → 网络
              ↑ 拷贝(1)      ↑ 拷贝(2)
              两次上下文切换，内核全程参与

RDMA：
应用 buffer ←→ 本端网卡（直接 DMA 读）→ 网络 → 对端网卡（直接 DMA 写）→ 对端应用 buffer
```

**三个核心机制**：

| 机制                 | 做什么                                   | 归属                                 |
| ------------------ | ------------------------------------- | ---------------------------------- |
| 内存注册（`ibv_reg_mr`） | 把内存登记给网卡：pin 住页，并把"虚拟地址→物理地址"的翻译表交给网卡 | 【软】用户态调用 + 内核 pin<br>【硬】网卡保存并使用这张表 |
| 队列对（Queue Pair）    | 发送队列 + 接收队列，应用往里面投递工作请求               | 【硬】网卡维护消费指针<br>【软】应用维护生产指针         |
| 完成队列（CQ）           | 完成的请求回到这里                             | 【硬】网卡写入<br>【软】应用轮询 `ibv_poll_cq`   |

**四种操作**：

| 操作          | 语义                          |
| ----------- | --------------------------- |
| RDMA Write  | 把本端数据推进对端内存。**单边**，对端进程毫不知情 |
| RDMA Read   | 从对端内存拉数据。**单边**             |
| Send / Recv | **双边**，对端应用必须先投递接收 buffer   |
| Atomic      | 在对端内存上做 fetch-add / CAS     |

**单边 vs 双边是 RDMA 最重要的概念区分**：单边操作完全不需要对端软件参与（这是它快的来源），也因此难用——对端根本不知道数据来了。

**和 GPU 内部 C2C/D2D 的关系**：概念同构（都是"一个设备直接搬另一个内存域的数据，不经过那个域的处理器"），但约束完全不同——见 [[c2c-crosscard#片内 C2C/D2D 与跨卡 DMA 的设计轴]]。
