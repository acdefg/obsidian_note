### 1. 近似计算电路怎么实现？

**要给的分类**（先分类，再举一个例子，最后报指标）：

| 层次 | 做法 | 砍掉了什么 |
|---|---|---|
| 加法器 | **LOA**（低位用 OR 代替加法）、**ETA**（高低位分段，低位近似）、**speculative adder**（低位先猜进位、错了再修） | 进位链 → 关键路径 |
| 加法器 | **近似全加器**（改真值表，少几个晶体管） | 器件数 / 翻转 |
| 乘法器 | **截断部分积**（丢低 k 位 + 补偿项）、**近似 Booth 编码**、**近似 4-2 compressor** | Wallace 树的规模 |
| 乘法器 | **对数乘法器**（log 域相加） | 整个乘法阵列 |

**为什么能省功耗**（面试官说"从降功耗角度"，要给出机制而不是形容词）：
- 动态功耗 ∝ 电容 × 电压² × 翻转率。近似电路**少晶体管**（电容↓）+ **进位链短**（可降压，电压项是平方收益）+ **翻转少**。
- 关键路径变短 → 同一工艺下可提频，或维持频率降电压。

**必须补的一句**：近似只在**允许错误的方向**上用——图像/视频（PSNR 兜底）、神经网络推理（对低位不敏感）、无线基带。**控制通路、地址计算、累加器的高位绝不能近似**。

> 我的挂靠点：[[mixed-precision-cim]] 里的 bit-slicing 与 INT8/INT4 量化误差，本质就是"哪些位可以丢"。从量化讲到近似电路，是同一件事的两个层面。

### 2. CNN 的 PE 接口和电路结构

**先给一张最小的 PE**：乘法器 + 累加器 + 三个寄存器（weight / activation / partial sum）。

**接口按数据流决定方向**——这是这题的得分点，不要只背引脚：

| 数据流 | 权重 | 激活 | 部分和 | 接口特点 |
|---|---|---|---|---|
| **WS**（weight stationary） | 预载后不动 | 从左/上流入 | 向下流出 | 权重口只在 load 阶段忙 |
| **OS**（output stationary） | 流入 | 流入 | **留在 PE 累加** | psum 口不出 PE，省带宽 |
| **RS**（row stationary） | 行列复用 | 行列复用 | 行内流动 | 复用因子最高，控制最复杂 |
| **IS**（input stationary） | 流入 | 固定 | 流出 | 适合激活复用高的场景 |

**控制信号**：`load_weight`、`en`（累加使能）、`clear`（清零 psum）、`mode`（累加 / 直通）、**精度选择**（INT8 / INT4 / FP16 的乘法器配置）。

**存储层次**（第三问"存储层次"要答）：PE 内寄存器堆 → 阵列旁的 global buffer（SRAM）→ L2/DRAM；两层之间用 **double buffering / ping-pong** 隐藏搬运。

**必答的数字感**：psum 位宽要比乘法结果宽——`INT8×INT8 → 16 位乘积`，累加 K 次需要 `16 + log2(K)` 位，否则溢出。

### 3. 近似计算精度怎么评估？

**三层指标，从电路到应用**：

| 层 | 指标 | 用途 |
|---|---|---|
| 电路级 | MAE / MRE / RMSE / **最大绝对误差** | 快速筛选，最大误差决定 worst case |
| 统计级 | 误差**是否有偏**（bias）、误差分布、是否与输入相关 | 有偏误差会在累加中**累积放大** |
| 应用级 | PSNR / SSIM（图像）、top-1/top-5（NN）、BER（通信） | 最终判据，决定能不能用 |

**评估方法（面试要讲流程）**：
1. 写 bit-accurate 的近似算子模型（和 RTL 逐位对齐）；
2. 在真实数据集上替换原算子，跑应用级指标；
3. 扫参数画 **精度–面积–延迟–功耗** 的 Pareto 前沿；
4. 特别验证**误差累积**：单个乘法器误差 1%，K 次累加后可能到 K 倍——所以要在真实数据分布上测，不能用均匀随机输入。

### 4. MoE 大模型和它需要的计算模块

**原理一句**：把 FFN 拆成 N 个 expert，router 为每个 token 选 top-k 个 expert 计算，实现"参数量大、激活量小"。

**计算模块清单**：

| 模块 | 计算 | 硬件特征 |
|---|---|---|
| Router | 线性层 + softmax + top-k | 小 GEMM + 排序/top-k，延迟敏感 |
| Expert FFN | 多个独立 GEMM | **稀疏/分组 GEMM**（gather-scatter） |
| Token dispatch / combine | all-to-all | **跨卡通信**，是 MoE 的主要瓶颈 |
| Load balance | aux loss / capacity factor | 负载不均 → straggler |

**必答的取舍**：MoE 省的是**计算量**，不省**通信量**和**显存**。Expert 并行（EP）时 all-to-all 占比可能超过 30%。

### 5. Transformer 结构和计算模块

**四个 GEMM + 两个非 GEMM**：

```
X → [QKV 投影: 3 个 GEMM] → [QKᵀ: GEMM] → softmax → [AV: GEMM] → [输出投影: GEMM]
  → [FFN: 两个 GEMM + 激活] → LayerNorm / residual
```

**硬件映射**：
- GEMM → Tensor Core / 脉动阵列（复用高，适合大矩阵）
- softmax → 行最大值归约 + exp 单元 + 行求和归约，是**非 GEMM 的专用通路**
- LayerNorm → 归约 + 除法/开方
- **KV cache** → decode 阶段的主要访存来源

**prefill vs decode**：prefill 是 compute-bound（大矩阵），decode 是 **memory-bound**（每 token 只算 1 行，但要读整个 KV cache）。这条一定要说，它决定硬件该优化算力还是带宽。

### 6. Attention 的输入是什么？怎么得到的？

**结构上**：输入是上一层输出的 hidden states `X ∈ R^{N×d}`，经三个**可学习权重矩阵**投影：

```
Q = X·W_Q,   K = X·W_K,   V = X·W_V      （W_Q, W_K, W_V ∈ R^{d×d_k}）
```

**语义上**（这题真正考的是这个）：
- **Q（query）**：当前位置"想找什么"；
- **K（key）**：每个位置"能提供什么"的索引；
- **V（value）**：每个位置"实际提供的内容"。
- 相似度 `QKᵀ` 决定"看谁"，权重乘 `V` 决定"取什么"。

**怎么得到的**：权重是**训练学出来的**；推理时由当前层的输入投影而来；历史 token 的 K/V 存进 **KV cache**，避免重算。

**别漏**：多头把 `d` 拆成 `h` 份，每头独立做 attention；位置信息通过位置编码（或 RoPE 作用在 Q/K 上）注入——**Attention 本身对顺序无感知**，这是常见追问。

### 7. 矩阵乘法电路怎么实现？性能怎么估？

**三种实现**：脉动阵列（systolic）、向量处理单元（SIMD/VPU）、通用 MAC 阵列 + 数据流调度。

**性能公式（要能当场写）**：

```
峰值算力   = S² × 2 × f          // S×S 个 MAC，每个 MAC = 2 ops
实际算力   = 峰值 × 利用率
tile 数    = ⌈M/S⌉ × ⌈N/S⌉ × ⌈K/S⌉
周期数     ≈ tile 数 × S          // 简化模型，未计填充与流水启动
利用率     = 有效 MAC 数 / (S² × 周期数)
算术强度   = 2MNK / [(MK + KN + MN) × bytes_per_elem]
```

**必须讲的两个损耗**：
- **边缘填充**：M/N/K 不是 S 的整数倍时，tile 内有效 MAC 变少 → 利用率下降；
- **带宽墙**：算术强度低于机器的 ops/byte 时变成 memory-bound，此时提阵列规模没用。

**优化手段**：tiling（提高复用）、double buffering（隐藏搬运）、权重/激活的不同驻留策略。

> 挂靠：[[computer-arch]] 的「数据流四分类与复用因子」、[[rram-cim]] 的「tiling 与阵列映射」。

### 8. 项目深挖（共享屏幕画架构图）

**画图顺序（固定成肌肉记忆）**：
1. **边界**：输入/输出、时钟域、复位、与外部模块的接口；
2. **主数据通路**：从输入到输出的一条最粗的线，标位宽；
3. **控制与状态**：状态机、计数器、握手信号；
4. **存储**：buffer / FIFO / cache 的位置和容量；
5. **一个瓶颈 + 一次优化**：说出"这里原来是 X，改成 Y 之后指标从 A 到 B"。

**面试官在看的**：不是图画得多漂亮，而是你能不能**边画边讲清每个模块为什么存在**。画到一半被追问"这个信号为什么需要"时，答不上来就是硬伤。

### 3. DMA 架构

**组成（画成六个块）**：

| 块 | 作用 | 关键设计点 |
|---|---|---|
| 描述符队列 | 存放搬运任务 | SGL、链式描述符、doorbell 触发 |
| 地址翻译 | IOVA → PA | IOMMU/SMMU，TLB 缺失时的延迟 |
| 读引擎 / 写引擎 | 发起读写事务 | 分离的双向通道，可全双工 |
| 数据缓冲 | 跨时钟/跨宽度 | FIFO 深度影响吞吐和背压 |
| 仲裁 / QoS | 多通道竞争 | 轮询 + 优先级 + credit 隔离 |
| 完成通知 | MSI-X / 事件 | 完成顺序 vs 发起顺序 |

**带宽的判据（必答公式）**：Little's law

```
可持续带宽 B ≈ outstanding_bytes / 往返延迟 L
要跑满 B，需要  outstanding ≥ B × L / burst_size
```

**可验算的例子**：目标 1 TB/s、往返延迟 500 ns、burst 128 B →

```
outstanding ≥ 1e12 × 500e-9 / 128 ≈ 3900 笔
```

所以要跑满这条链路，DMA 必须有近 4000 笔在途请求，或者加大 burst。**这解释了为什么高带宽 DMA 都在堆 outstanding 和 burst，而不是堆频率。**

**追问预判**：跨卡与本地流量竞争怎么隔离（→ 多 VC + 加权轮询 + per-VC credit）；HOL 在哪一级产生（→ 共享队列/共享 VC/共享 credit 三选一，要说清是哪一级）。

### 4. scratchpad 的乒乓 pipeline

**机制**：scratchpad 是**软件显式管理**的片上 SRAM，没有 tag、没有替换、地址就是数据位置。

```
      ┌── buffer A ──→ 计算读 A
DMA ──┤
      └── buffer B ──→ 下一轮
         （A 在算时，DMA 往 B 写；B 写完再交换角色）
```

**三级流水**：`global → L2 → scratchpad → compute`，实际是 **load / compute / store** 三段重叠。

**关键参数**：
- buffer 大小 = **一个 tile**；乒乓要 **2×**，三级缓冲 3×；
- 同步点用 barrier / event / `cp.async` 的 commit group；
- 能隐藏的时间上限 = **一个 stage 的时间**；搬运抖动超过它就 stall。

**带宽判据**：`t_load = tile_bytes / 搬运带宽`，`t_compute = tile_MACs / 算力`。若 `t_load > t_compute`，加计算阵列无效——**memory-bound，要改 tiling 或提高复用**。

**和 cache 的区别（必答）**：cache 靠硬件猜，命中率不确定；scratchpad 靠编译器算，**延迟可预测**。AI 加速器选 scratchpad 就是为了把"不确定"变成"可调度"。

### 5. 矩阵 tiling

**为什么 tiling**：把"每次都要从 DRAM 取"变成"片内复用"，提高算术强度。

**tile 尺寸怎么定（反解）**：设 tile 为 `M_t × K_t` 的 A 和 `K_t × N_t` 的 B

```
容量约束： (M_t·K_t + K_t·N_t) × bytes ≤ scratchpad_size / 2   // /2 是乒乓
算术强度： AI = 2·M_t·N_t·K_t / [(M_t·K_t + K_t·N_t) × bytes]
```

选 tile 的目标是让 **AI ≥ 机器的 ops/byte 拐点**（roofline 的脊点），再大的 tile 只增加面积不增加性能。

**可验算的例子**（M=N=K=1024、S=32、f=1 GHz）：

```
峰值算力 = S² × 2 × f = 32² × 2 × 1e9 = 2.048 TFLOP/s
tile 数  = (1024/32)³ = 32³ = 32768
周期数  ≈ tile 数 × S = 32768 × 32 = 1,048,576 ≈ 1.05 ms
校验：总 MAC = 1024³ = 1.07e9，1024 MAC/cycle → 同为 1.05e6 拍 ✓
```

**必答的两个损耗**：边缘填充（非整数倍）、带宽墙（AI 不够时加阵列无效）。

### 6. 跨时钟域合流（异步 FIFO + 仲裁）

**结构**：

```
源 A (clk_a) → 异步FIFO_A ─┐
源 B (clk_b) → 异步FIFO_B ─┼→ 仲裁器（目的域 clk_d 单时钟）→ 出口
源 C (clk_c) → 异步FIFO_C ─┘
```

**三条必须讲清的点**：

1. **隔离**：每个源一个 FIFO。一个源满不会堵住其他源——这就是**在队列粒度上消除 HOL**。
2. **仲裁只在目的域做**。仲裁器不能跨域，否则组合路径穿过同步器。
3. **FIFO 的 `empty` 是保守的**：指针同步有 2 拍延迟，所以数据可能已经到了但 `empty` 还没撤销 → **吞吐略降，但安全**。这是异步 FIFO 的固有代价，不是 bug。

**空满判定（gray code）**：

```verilog
// 写指针/读指针用 gray code 跨域，2FF 同步
empty: rptr_gray_sync == wptr_gray
full : wptr_gray_sync == {~rptr_gray_sync[AW:AW-1], rptr_gray_sync[AW-2:0]}
// 深度必须是 2 的幂；指针多一位用于区分满/空
```

**backpressure**：`ready` 反向也要跨域 → 用 credit（把反压离散化）比直接传 ready 线更安全。

**合流后的乱序**：多源汇聚后请求/响应要能配对 → 每笔事务带 **ID/tag**，返回时按 tag 重排。

### 7. 多时钟建模

**核心原则：不要在模型里做"全局同拍"。** 一旦全局同拍，CDC 的吞吐损失就建不出来，模型会系统性高估性能。

**四个建模要素**：

| 要素 | 建模方式 |
|---|---|
| 各域时钟 | 每个域按自己的 period 往事件队列插边沿，不用求 LCM |
| 同步器 | 建成**目的域的固定延迟**（2FF → 2 个目的周期） |
| 异步 FIFO | 建"指针同步延迟 + empty 保守性"，否则吞吐对不上 RTL |
| 亚稳态 | 功能模型里不建；只在可靠性分析里按 MTBF 估算 |

**精度取舍**：
- 固定延迟近似足够回答"这个 CDC 损失多少吞吐"；
- 只有要分析**亚稳态概率**时才需要 MTBF：

```
MTBF ∝ e^(t_resolve / τ) / (f_clk × f_data)
```

含义：增加同步器的分辨时间 `t_resolve`（多打一拍/用更快的触发器）能**指数级**改善 MTBF——这是面试里最值钱的一句。

**和我项目对接**：cosim 里跨域对齐点必须落在**目的域的采样沿**，否则 scoreboard 会周期性错拍。

### 8. 多 chiplet 中 SerDes 的同步

**接收侧的四级同步**（从上到下）：

| 级 | 做什么 | 关键机制 |
|---|---|---|
| ① 时钟恢复 | 从数据边沿恢复时钟（CDR） | 恢复时钟与本地时钟有 **ppm 级频偏** |
| ② 弹性缓冲 | 吸收频偏造成的滑动 | 频偏累积到一定程度要"插/删" |
| ③ 时钟校正 | 插入/删除 **idle 或 SKP 字符** | **只能删 idle，不能删数据** |
| ④ 通道对齐 | 多 lane 去偏斜、通道绑定 | lane deskew + 多通道对齐 |

**弹性缓冲深度的算法（可验算）**：

```
每次校正之间允许累积的位滑移 = 频偏(ppm) × 1e-6 × 校正间隔(bit)
例：两端共 200 ppm，校正间隔 10^4 bit
    → 滑移 = 200e-6 × 1e4 = 2 bit
    → 缓冲深度几个字就够（但要覆盖最大包长，不能按平均值算）
```

**为什么必须做**：发送端和接收端是两个独立晶振，长期必然累积滑移；不吸收就会丢位或重复位。

**追问**：链路训练流程（对齐 → 均衡 CTLE/DFE → 协商速率/宽度）、CRC/重传、lane repair（坏 lane 用备用 lane 替换）。

> ⚠️ 具体速率/ppm 规格**不确定就别说数字**，定性讲清"恢复时钟 — 弹性缓冲 — 时钟校正 — 通道对齐"四层即可。可参照 [[interconnect-survey]]。

### 9. chiplet 之间的接口以及行为

**三层结构（按 UCIe 的分法）**：

| 层 | 内容 | 关键点 |
|---|---|---|
| **物理层** | 并行 D2D（先进封装，短距）或 SerDes（标准封装，长距） | 先进封装 bump pitch 更小 → 能效和带宽密度更高 |
| **die-to-die adapter** | CRC、**ARQ 重传**、链路状态管理、lane repair | 这一层是 D2D 特有的，普通 SerDes 协议里没有 |
| **协议层** | PCIe / CXL / **streaming（自定义）** | streaming 无一致性，CXL 才有内存语义 |

**行为顺序（面试按这个讲）**：

```
上电/复位 → 链路训练（速率、宽度、lane 对齐）
         → 参数协商（协议模式、credit 初值）
         → 链路 up，开始传事务
         → 出错：CRC 失败 → ARQ 重传；lane 坏 → repair；不可恢复 → 链路降级/重训
```

**与片内 D2D 的区别（我的经验能直接答）**：

| | 片内 D2D | 跨 chiplet / 跨卡 |
|---|---|---|
| 延迟 | 几十 ns | 几百 ns 到 µs |
| 错误率 | 基本无错，不需重传 | 有误码，必须 CRC + ARQ |
| 协议 | 自定义简单协议 | 要跑标准（UCIe/CXL）或自定义 streaming |
| 同步 | 同源时钟或简单握手 | 独立时钟 → CDR + 弹性缓冲 |
| 建模 | 周期级 | 事件级 + 延迟分布 |

**一句话总结**：chiplet 接口的本质是**把"片内假设"逐个放弃**——放弃同源时钟（→ SerDes 同步）、放弃无误码（→ CRC/ARQ）、放弃低延迟（→ outstanding 和缓冲要重算）。

### 1. Transformer 每一层怎么加速

**按层拆成"矩阵 / 归约 / 逐元素"三类**，这是回答的骨架：

| 层 | 计算形态 | 硬件去处 | 加速手段 |
|---|---|---|---|
| Embedding | 查表 | 访存 | 表放片上、合并访问 |
| QKV / 输出投影 | GEMM | 脉动阵列 / Tensor Core | 量化、融合 |
| QKᵀ / AV | batch GEMM | 同上 | tiling、FlashAttention 分块 |
| Softmax | 行归约 + exp | 向量单元 / SFU | 与 GEMM 流水重叠、在线 softmax |
| LayerNorm | 行归约 + rsqrt | 归约树 | 与上一层融合 |
| FFN | 两个大 GEMM + 激活 | 阵列 | **算力主战场**，量化收益最大 |
| Residual | 逐元素加 | 向量单元 | 与上一层 epilogue 合并 |

**核心判断**：Transformer 的时间几乎全在 GEMM 上，所以加速的主线是"**让矩阵尽量大、让归约尽量重叠**"。softmax/LN 本身算得少，但它们是 GEMM 之间的**同步点**，处理不好会变成流水线气泡。

### 2. LayerNorm 和 BatchNorm 的区别（要答到"能不能折叠"）

| | BatchNorm | LayerNorm |
|---|---|---|
| 归一化维度 | **batch 维**（跨样本，同一通道） | **特征维**（单样本内，同一 token） |
| 统计量 | 训练用当前 batch，推理用 running mean/var | 直接用当前输入算，训练推理一致 |
| 对 batch size | 敏感（batch 小则统计不准） | 不敏感 |
| 典型场景 | CNN | Transformer / 变长序列 |

**硬件上最关键的一条**：**BN 在推理时可以折叠进前一层，LN 不能。**

```
BN:  y = γ(x-μ)/σ + β  →  W' = W·γ/σ,  b' = γ(b-μ)/σ + β     // 推理时零开销
LN:  μ、σ 依赖当前输入 → 必须在线算归约 + rsqrt                 // 每层都要算
```

所以硬件里 LN 是**实打实的行归约单元**（一行 512–4096 个元素，两级归约树），而 BN 只是一个已融合的 scale/shift。

### 3. 多核加速 fc_layer 具体 tiling 怎么做

`fc: Y[M,N] = X[M,K] · W[K,N]`

**三种切法**：

| 切法 | 每核算什么 | 需要广播什么 | 适用 |
|---|---|---|---|
| 切 N（输出通道） | `X[M,K] · W[K,N/c]` | X 全量 | batch 大、N 大 |
| 切 M（batch） | `X[M/c,K] · W[K,N]` | W 全量 | batch 大、M 大 |
| **split-K** | 部分和 → all-reduce | 无广播，但要 reduction | M、N 都小（decode） |

**选法判据：让广播量最小。**

可验算的例子：M=1024、N=4096、K=4096、4 核

```
切 N：每核拿 W 的 1/4（4096×1024），广播 X = 1024×4096 = 4.2M 元素
切 M：每核拿 X 的 1/4（256×4096），广播 W = 4096×4096 = 16.8M 元素
→ 切 N 的广播量是切 M 的 1/4，选切 N
```

**每核内部**再做一次小 tiling 进 scratchpad，配 ping-pong；这就是"核间切分 + 核内 tiling"两层结构。

### 4. 不同并行的多核架构的区别

| 并行 | 切什么 | 通信原语 | 通信/计算比 | 对硬件的要求 |
|---|---|---|---|---|
| **DP** 数据并行 | 切 batch | 梯度 all-reduce | 与 batch 成反比 | 高带宽 broadcast |
| **TP** 张量并行 | 层内切矩阵（列并行 + 行并行） | 每层 2 次 all-reduce | **高且频繁** | 极低延迟、高带宽（节点内 NVLink） |
| **PP** 流水并行 | 按层切 | 激活/梯度的点对点 | 中 | 大 buffer、micro-batch 填 bubble |
| **EP** 专家并行 | MoE 的 expert 分片 | **all-to-all** | 高（token 路由） | all-to-all 带宽 |

**一句话**：DP/PP 可以跨节点，**TP 和 EP 基本被限制在超节点内**——因为它们对延迟和 all-to-all 带宽的要求，跨节点网络扛不住。

### 5. systolic array 的 input 和 weight 都是怎么给的

以 TPU 式 **weight stationary** 为例：

```
weight：开机/换 tile 时一次性预载进每个 PE 的寄存器，之后静止
activation：从左侧流入，沿行向右逐拍传递
partial sum：从上侧流入，沿列向下逐拍累加
```

**为什么必须"错拍"（skew）**：

```
PE(i,j) 需要第 (i+j) 拍才收到对应的 activation
→ 第 i 行的输入要延迟 i 拍再进阵列
不 skew 的话，数据在错位的周期到达，结果是错的
```

**带宽与复用**（面试官想听的数字）：

```
S×S 阵列，每个 weight 被沿行复用 S 次，每个 activation 被沿列复用 S 次
→ 每拍只需喂入 S 个 activation，权重只在换 tile 时搬运
→ 这是 systolic 能效高的根本原因：复用来自"数据在 PE 间流动"，而不是寄存器堆
```

### 6. 为什么这么设计？设计前怎么考虑资源利用率？

**设计出发点**：目标 workload 的 GEMM 形状决定阵列形状，而不是反过来。

**利用率的两个损耗源**：

```
① 形状不匹配：M 或 N 小于 S 时，阵列有 (1 - M·N/S²) 的空闲 PE
   decode 阶段 M=1 → 利用率 1/S，几乎全空
② 尾部效应：tile 数不能整除时，最后一轮只用了部分 PE
```

**所以架构取舍是**：

- 训练 / prefill（大 M）→ 大阵列，峰值优先；
- 推理 decode（M=1）→ 大阵列反而浪费，需要**矩阵-向量模式**或**批处理（continuous batching）**把 M 撑起来；
- 这就是为什么推理芯片常配"小阵列 + 高带宽"，而不是一味堆 MAC。

### 7. systolic array 对比传统 SIMD core

| | SIMD core | Systolic array |
|---|---|---|
| 控制 | 指令译码 + 寄存器堆 + 指令调度 | 几乎无指令，PE 只有局部寄存器 + MAC |
| 数据复用来源 | 寄存器堆 / 指令级复用 | **数据流过多个 PE**（空间复用） |
| 灵活性 | 高（分支、不规则、变长） | 低（只适合规则稠密计算） |
| 能效 | 较低（取指、译码、寄存器堆开销） | 高 |
| 面积效率 | 较低 | 高 |
| 编程 | 编译器/向量化 | 需要专门映射（tiling + 数据布局） |

**别把 SIMT 混进来**（面经作者就卡在这）：

- **SIMD** = 一条指令作用于多个数据（向量）；
- **SIMT** = SIMD 的多线程版，warp 内锁步但每个线程有自己的状态和调度（GPU）；
- **Systolic** = 数据在 PE 间流动，没有指令流。

三者是三个正交的概念：**SIMD/SIMT 说的是"一条指令管多少数据"，systolic 说的是"数据怎么在阵列里走"。**

### 8. CNN 模型量化和剪枝怎么做

**量化**：

| | PTQ（训练后） | QAT（量化感知训练） |
|---|---|---|
| 做法 | 校准集统计 min/max 或 KL/percentile → scale/zero-point | 插入 fake quant，用 STE 反传 |
| 成本 | 低，无需重训 | 高，要重训 |
| 精度 | 一般够 | 更好，尤其低比特 |

**工程细节（面试官会追）**：
- **粒度**：weight 用 **per-channel**（每个输出通道一组 scale），activation 用 per-tensor；
- **对称性**：weight 对称量化（零点为 0），activation 非对称；
- **requant**：累加结果 `acc` 乘一个定点数 `M` 再右移，避免浮点除法；
- **bias** 保持高精度（INT32），否则小 bias 被量化掉。

**剪枝**：

| | 非结构化（权重级） | 结构化（通道 / 滤波器级） |
|---|---|---|
| 稀疏模式 | 随机 | 整通道/整行 |
| 硬件友好度 | 差（需要稀疏引擎） | **好**（直接减小 GEMM 维度） |
| 代表 | 2:4 结构化稀疏（Ampere 支持） | 直接砍 N 或 K |

**一句话**：剪枝要"真省算力"，必须做成**结构化**；非结构化稀疏在通用阵列上往往只省了存储、没省时间。

### 9. 层融合是怎么在硬件上实现的

**动机**：中间结果每写回一次 DRAM，就多一次带宽开销。融合把"写回 + 再读"变成"片上直传"。

**三种典型融合**：

1. **Conv + BN + ReLU**：BN 折叠进卷积权重（见第 2 题），ReLU 放进 epilogue —— 零额外成本；
2. **Conv + Conv**：上一层输出留在片上 buffer，直接作为下一层输入；
3. **Attention 的 softmax 融合**（FlashAttention）：把 `QKᵀ → softmax → AV` 分块做，**不把 S×S 的中间矩阵写回 HBM**。

**硬件实现要点**：

| 要素 | 做法 |
|---|---|
| 中间结果存放 | 片上 scratchpad / 行 buffer，不落 DRAM |
| 模块间传递 | 流水线 FIFO 直连，生产者-消费者 |
| 调度 | 编译器做融合 pass，生成融合后的 descriptor |
| 代价 | 片上 buffer 增大；依赖链变长，可能降低并行度 |

### 11. "用 SystemC TLM2.0 还是 C++？LT 还是 AT？"

这题是我的主场，答法应当**先给分工，再给判据**：

| | SystemC TLM-2.0 | 纯 C++ 自研模型 |
|---|---|---|
| 抽象层 | 事务级，标准 payload/socket | 自己定，想多细就多细 |
| 复用 | 可与第三方 VIP / 虚拟平台对接 | 只能内部用 |
| 速度 | LT 快、AT 慢（phase 往返） | 通常最快（无框架开销） |
| 适用 | SoC 总线建模、虚拟平台、软硬协同 | 性能模型、设计空间探索、快速迭代 |

**"两种都用"才是正确答案**，然后补一句分工：

> 事务级和虚拟平台用 TLM-2.0，因为要和软件栈、第三方模型对接；纯性能模型用 C++，因为要跑参数扫描、几百万次迭代，框架开销不能忍。

**LT vs AT**：

- **LT**（`b_transport`）：调用即完成，延迟靠引用累加 → 软件开发、系统级初估；
- **AT**（`nb_transport_fw/bw` + phase）：能表达流水和反压 → 架构探索；
- 判据：**要不要建反压和流水时序**。要 → AT；不要 → LT。

详细的接口名、phase 流程、DMI、quantum 见 [[2026-10-24-第一场面试记录]] §3.3。

### 2. 模拟器精度达标、流片后不达标，怎么分析

**第一刀：误差是系统性的还是随机的。** 这一刀决定后面所有方向。

| 现象 | 更可能的原因 | 下一步 |
|---|---|---|
| 每次都偏同一个方向、随层数累积 | **数值/量化/舍入** | 查舍入模式、累加顺序、饱和 |
| 复现率低、和电压/温度/频率相关 | **硬件/时序** | 扫 PVT corner、查 margin、查 ECC |
| 只有某些输入错、位置固定 | **功能 bug / 存储缺陷** | 定位到具体单元/地址 |

**具体动作（按顺序）**：

1. **对齐口径**：模型版本、量化参数、校准集、指标定义是否与仿真完全一致。很多"不达标"死在这一步。
2. **逐层 dump 比对**：同一组输入，芯片和模型各 dump 每层输出，找到**第一次偏离的层**——问题一定在这一层或它的输入。
3. **数值层排查**：round-to-nearest 还是 truncation、累加是串行还是树形（顺序不同结果不同）、有没有中途饱和/溢出、denormal 怎么处理。
4. **定向向量**：全 0、全最大、正负交替、单点非零。**定向向量能过、随机向量不过**，通常是累加溢出或舍入。
5. **PVT 扫描**：电压降 5%、频率升 5%、温度到上下限。随机错误随 PVT 恶化 → 时序 margin 不足。
6. **回灌校准**：把芯片实测的误差分布回灌到模型里，让模型和硅片重新对齐。

**一句话结论**："系统性偏差查数，随机性偏差查时序，局部固定错查单元。"

### 3. 为什么选 AI 芯片？怎么看寒武纪和 NVIDIA / 华为的竞争

**动机（30 秒）**：AI 芯片是"算法—架构—电路"耦合最紧的领域，我的背景正好横跨这三层：做过电路（润石、RRAM）、做过 SoC 集成（算能）、做过性能建模（摩尔线程）。在这个方向上，我的经验不会浪费。

**竞争格局（按三层拆，别排座次）**：

| 层次 | 比什么 | NVIDIA | 华为昇腾 | 寒武纪 |
|---|---|---|---|---|
| 短期 | 峰值算力 / 制程 | 领先 | 接近（受制程限制） | 可用 |
| 中期 | 能效 / 集群规模 | NVLink + 超节点 | 全栈自研 + 系统能力 | 专用架构 + 国产供应链 |

- 华为的优势是**系统级能力**（芯片 + 网络 + 云 + 框架），不只是单芯片。

### 4. INT8 结果偏差 0.1%：量化误差还是 functional bug

**第一刀：0.1% 到底是不是"错"。** INT8 量化本身的相对误差典型就在 0.1%–1% 量级，先确认：
- 是**逐元素最大相对误差**，还是**超阈值元素的比例**，还是**端到端 accuracy 下降**？
- 如果端到端只掉 0.1%，那可能完全正常。

**第二刀：构造"零量化误差"的输入。** 这是本题的核心实验：

```
把所有输入限制为 INT8 可精确表示的值（0、±1、±2 的幂、±127）
→ 此时 scale 是 1，量化误差严格为 0
→ 如果结果仍然错：一定是 functional bug，与量化无关
→ 如果结果全对：问题在量化/舍入链路，不在计算单元
```

**第三刀：如果确认是 functional bug，继续缩**：

1. **单 PE 扫描**：其他 PE 输入置 0，只激活 PE(i,j)，遍历整个阵列 → 找恒错的单元（stuck-at、进位链断）。
2. **位级分析**：把错误值的二进制打出来，看是否集中在某几位。**某一位固定错** → 数据通路断线；**低几位随机错** → 进位/压缩树。
3. **边界值**：`127 × 127`（累加器正溢出）、`-128 × -128`、正负交替（进位传播最长）。
4. **K 维边界**：累加长度不是 tile 整数倍时，最后一段的 partial sum 是否正确回写。
5. **误差直方图**：量化误差应当对称、有界；functional bug 会产生离群的大误差，双峰分布。

**判据总结**：

| 特征 | 判定 |
|---|---|
| 零量化输入仍错 | functional bug |
| 误差集中在特定位/特定 PE | functional bug |
| 误差对称、有界、随幅度增大 | 量化误差 |
| 只有 K 边界错 | 累加/回写逻辑（仍是功能） |

### 5. DMA 非对齐地址搬运 corruption：对齐 bug 还是 burst 长度

**核心实验：二维扫描 `offset × length`。** 这是能把两个假设分开的最小实验：

```
地址 offset 扫 0 .. align-1（比如 0..127，覆盖 128B 对齐周期）
传输长度 length 扫 1 .. max_burst（比如 1..256）
每个组合单独跑一次，用固定 pattern（0xAA/0x55 交替）标记每个字节
→ 记录第一个出错的字节位置
```

**读结果的方式**：

| 错误图形 | 根因 |
|---|---|
| 错误只随 **offset** 变化，与 length 无关 | **地址对齐/边界处理**（低位被 mask 错、跨边界没拆分） |
| 错误只随 **length** 变化，且与 burst 取模相关 | **burst 长度计算 / 拆分逻辑** |
| 错误出现在两条"带"的交界 | **跨边界拆分**：首段非对齐 + 中间整 burst + 尾段 |
| 数据整体偏移 N 字节 | 地址生成错位（最常见：`addr & ~(align-1)` 用错） |
| 数据重复/丢失一段 | 长度累加错（SGL 每段长度没累加，或末段多算） |

**再往下钻**：

1. **看第一个错的字节位置**：和 128B/4KB 边界的关系。若总在 `addr % 128 == 0` 处 → 边界拆分 bug。
2. **检查 4KB 跨页**：DMA 必须把跨 4KB 的 burst 拆成两个事务（AXI 不允许跨 4KB），漏拆会导致从设备侧地址回绕。
3. **检查内部信号**：地址是否被对齐 mask、burst 计数器是否在拆分时清零、SGL 描述符的 length 是字节还是 beat。
4. **回读校验**：写完后用非 DMA 通路（CPU 或调试口）读回，区分"写错"和"读错"。

**一句话**：**offset 决定"从哪开始"，length 决定"搬多少"，二维一扫，两个假设自然分开。**

### 6. FPS 低 20%：compute / memory / scheduling 怎么拆

**第一步：先算上界，再谈优化。** 用 roofline 算出该模型理论上应该跑多快：

```
计算时间上界 = 总 MAC 数 / (峰值 MAC 数 × 频率)
访存时间下界 = 总字节数 / 峰值带宽
理论时间 = max(计算, 访存)   （理想重叠）
→ 和实测比，20% 的差距落在哪一项上
```

**第二步：三个假设各自的可观测证据**：

| 假设 | 看什么指标 | 典型特征 |
|---|---|---|
| **compute bound** | MAC 利用率、阵列有效占用率 | 利用率高但算力没打满 → 频率/电压没到位 |
| **memory bound** | DRAM 带宽利用率、L2 命中率、sector 效率 | 带宽接近峰值但算力空闲 |
| **scheduling overhead** | kernel 间隔、DMA/计算 overlap 比例、同步等待 | 有大量空闲拍、双缓冲没起作用 |

**第三步：微基准分离。**

1. 只跑计算（数据已在片上、不搬）→ 测计算峰值；
2. 只跑搬运（不做计算）→ 测带宽峰值；
3. 两者叠加 → 看 overlap 效率。**如果 1+2 的时间 ≈ 实测，就是完全没有 overlap**。

**第四步：先排除"非架构原因"**（这 20% 最常见的来源）：

- **标称频率没跑到**：DVFS/thermal 降频，实测频率可能只有标称的 80%；
- **形状不匹配**：M/N/K 不是 tile 整数倍，阵列填充率下降；
- **尾效应**：最后几个 tile 只有部分 PE 在工作；
- **batch 太小**：decode 阶段 M=1，阵列大量空闲。

**回答的顺序**：先给 roofline 上界 → 再说三个指标怎么观测 → 最后按"先非架构、后架构"排查。**上来就说"优化 tiling"是最容易被追问到答不出的。**

### 7. SRAM banking 冲突：怎么设计 testcase

**先明确规则**：bank 数 B、bank 宽度、地址到 bank 的映射（通常是低位交织 `bank = (addr / word) % B`）。冲突的判定是**同一拍访问同一 bank 的不同地址**。

**用等价类组织，不要随机乱跑**：

| 类别 | 用例 | 期望 |
|---|---|---|
| 基线 | 单核顺序访问 | 吞吐 = 100% |
| 同 bank 同地址 | C 核同时读同一地址 | 支持 broadcast 则 100%，否则串行 |
| 同 bank 不同地址 | C 核打到同一 bank 的不同行 | **最坏情况，吞吐 ≈ 1/C** |
| 不同 bank | C 核各打一个不同 bank | 100%，无 stall |
| 随机分布 | C 核地址随机映射 | 冲突率应接近理论值 |
| burst 跨 bank | 一个 burst 跨两个 bank | 按 bank 边界拆分，不能丢数 |
| 读写混合 | 一半读一半写同 bank | 检查写优先/读优先策略 |
| RAW | 写后立刻读同 bank | 检查 bypass 和顺序 |

**断言与指标**：

- 在 testbench 里挂一个 **bank 监视器**：每拍统计每个 bank 被访问的次数；>1 且地址不同 → 必须 stall；
- 吞吐 = 有效访问数 / 总周期，和无冲突基线比；
- 覆盖：`bank 组合 × offset × burst 长度 × 核数`，用功能覆盖率确认每个 bank 组合都打到了。

**加分点**：区分两种冲突——
- **结构性冲突**（端口/容量不够，物理限制）；
- **映射冲突**（地址交织策略不好，可以通过改 mapping 缓解）。
前者只能靠加 bank，后者是架构可调的。

### 8. 稀疏推理 correctness：不同 sparsity pattern 都要验吗

**答案：不穷举 pattern，按"会不会走不同硬件路径"分等价类。** 这是验证岗最核心的思维。

**为什么不能穷举**：pattern 的数量是 `2^(M×K)`，不可行；而且绝大多数 pattern 对硬件是**同一条路径**，验了也不增加信息。

**按硬件分支划分等价类**：

| 维度 | 等价类 | 为什么会影响硬件 |
|---|---|---|
| 稀疏格式 | CSR / block sparse / 2:4 | 解析器走不同状态机 |
| 非零位置 | 首 / 中 / 尾 / 单元素 / 空行 | 指针边界、长度 0 |
| 与 tile 的关系 | 完全在 tile 内 / 跨 tile 边界 | 分块调度路径不同 |
| 稀疏度 | 0 / 极低 / 50% / 90% / 100% | 100% 全零走 skip 路径 |
| 数值 | 全零 / 最大正值 / 正负交替 | 累加溢出、符号处理 |
| metadata | index 越界 / 长度 0 / 对齐填充 | 解析器的错误处理路径 |

**随机 + 定向结合**：
- 定向覆盖上表的每个等价类（少量、精确）；
- 随机跑大量 seed 做统计覆盖（发现组合型 bug）；
- 用**稠密展开**做 golden：把稀疏矩阵还原成稠密，走成熟库算，比对结果。

**覆盖率指标**：功能覆盖率（上面的维度组合）+ 代码覆盖率 + 断言覆盖率。**closure 的标准是"所有等价类都打到了"，不是"跑够多少万条"。**

### 9. DVFS 跨频率结果一致性怎么验证

**判据：逐位一致。** 计算单元是确定性的，不同频率下结果必须**完全一样**，不是"统计上差不多"。

**四类用例**：

1. **同输入扫频率**：固定测试集（覆盖各种数据 pattern 和边界），在 f1…fn 各跑一遍，逐位比对。
2. **切换瞬态**（最容易出问题）：在传输**中途**切频——DVFS 的真实场景。检查在途事务是否丢/重/乱序。
3. **频率比扫描**：core : mem 的比值取 1:1、1:2、2:1，以及**非整数比**（如 3:2）——覆盖同步器的所有相位关系。
4. **电压 corner**：低压低频 / 高压高频 / 低压高频（最差时序），组合扫描。

**为什么频率切换会出错**：

- 异步 FIFO 的指针同步延迟随频率比变化，`empty` 的保守程度变了；
- PLL 重新锁定期间时钟不稳；
- 跨域握手如果在切换瞬间"半完成"，会卡死或丢事务。

**验证要求**：
- DVFS 切换前必须有 **quiesce（停流/隔离）** 机制，或者在途事务有足够 buffer 余量——验证要覆盖"切换指令与在途事务重叠"的场景；
- 长跑：每个频率下跑足够长时间，覆盖 ppm 累积导致的 FIFO 满/空边界。
