## 2. 项目深挖（30%）

> 每个项目都按同一模板准备：**一句话定位 → 必画图 → 关键决策与 trade-off → 量化口径 → 追问链 → 失败/权衡故事**。
> 量化数据必须能说清「基线是什么、怎么测的、是否公平」。

### 2.1 摩尔线程 — 异步通信 DMA（最高频，必须 L3）

- [ ] 一句话定位：为 C2C / D2D 提供可配置的异步数据搬运引擎，解决跨卡与本地流量竞争。
- [ ] 必画图：主机 / GPU / 对端 GPU 的 DMA 通路，标出 credit 反压路径、调度器、队列、完成通知。
- [ ] 关键决策与 trade-off：
  - [ ] C2C 与 D2D 的差异（协议、延迟、带宽、错误处理、地址空间）
  - [ ] HOL 的成因：共享队列 / 共享虚拟通道 / 共享 credit
  - [ ] 调度策略：怎么识别跨卡流量、怎么隔离、为什么能消除 90%
  - [ ] credit-based 流控：credit 粒度、初始值、归还路径、死锁避免
  - [ ] unbalance：检测方式（静态配置 / 动态统计）、缓解手段、开销
  - [ ] 多核同步：barrier / atomic / 完成通知 / 内存序
- [ ] 量化口径：3× 提升的 baseline、测试 pattern、是否含竞争场景、尾延迟是否变差。
- [ ] 追问链（准备到能连续回答）：
  1. C2C 和 D2D 为什么需要两套机制？能不能统一？
  2. HOL 具体阻塞在哪一级？你的调度器如何拿到「跨卡」信息？
  3. 消除 90% 流量竞争问题，剩下 10% 是什么？为什么消不掉？
  4. 3× 是带宽、延迟还是吞吐？测试用例覆盖哪些流量模式？
  5. credit 粒度怎么定？credit 不足时反压到软件还是硬件？会不会死锁？
  6. unbalance 是静态还是动态？统计窗口多大？误判怎么办？
  7. 多核同步和 DMA 完成通知怎么配合？有没有内存序问题？
  8. 功能模型与性能模型如何分工？模型误差多少？如何校准？
  9. benchmark 如何保证覆盖真实负载？有没有用 trace 回放？
  10. 如果重做一次，你会改哪三个设计？
- [ ] 失败/权衡故事：准备 1 个「方案被推翻」或「性能不达预期」的案例。
- 参考：[[study_note/cc_notes/DMA/引擎与机制/c2c-crosscard.md|C2C 跨卡]]、[[study_note/cc_notes/DMA/引擎与机制/engine.md|DMA 引擎]]、[[study_note/cc_notes/DMA/互连与RDMA/rdma.md|RDMA]]、[[study_note/cc_notes/DMA/预研综述/interconnect-survey.md|互连综述]]

### 2.2 摩尔线程 — 纹理压缩 + L1 乱序访存 + Cosim（高频）

- [ ] 一句话定位：纹理压缩模块的 Cmodel + 与 RTL 的 cosim，支撑乱序访存路径的架构探索与 debug。
- [ ] 必画图：texture request → 压缩块地址计算 → L1 乱序访存 → 返回重排 → 解压 → 输出。
- [ ] 关键决策与 trade-off：
  - [ ] 压缩块格式与随机访问：块大小、索引、endpoint、能否只解一块
  - [ ] 乱序访存的返回路径：tag、rob、重排缓冲、异常/错误处理
  - [ ] Cmodel 的抽象层级：功能正确 vs 时序近似，哪些细节必须建
  - [ ] cosim 的对齐点：请求边界、返回边界、周期 or 事务
  - [ ] 10k+ 组合用例的生成策略：参数组合、边界、随机、定向
  - [ ] TPU benchmark 的瓶颈分类：带宽、延迟、并行度、bank conflict
- [ ] 追问链：
  1. 为什么纹理压缩能省带宽？压缩比和画质的 trade-off 怎么定？
  2. BC / ASTC / ETC 的核心区别？你们选型考虑了什么？
  3. 压缩块如何支持随机访问？解压延迟怎么隐藏？
  4. L1 乱序访存的难点是什么？返回乱序如何重排？
  5. Cmodel 如何建模乱序？和 RTL 的误差主要来自哪里？
  6. cosim 的 scoreboard 怎么做？mismatch 如何定位到具体事务？
  7. 10k+ 用例如何保证覆盖率？用什么覆盖率指标？
  8. benchmark 的瓶颈分析方法是什么？最终优化了什么？
  9. 如果带宽翻倍，瓶颈会转移到哪里？
  10. descriptor constant cache 的一致性和命中率如何保证？
- [ ] 量化口径：压缩比、带宽节省、命中率、cosim 覆盖率、性能提升。
- 参考：[[study_note/cc_notes/计算机体系结构/cache-microarchitecture.md|Cache 微架构]]、[[study_note/cc_notes/压缩/格式/formats.md|压缩格式]]、[[study_note/cc_notes/压缩/硬件/hardware.md|压缩硬件]]
